# FAIRness assessment of the BnF workflow blueprint and its executable implementation

The assessment follows the FAIR guidelines for computational workflows proposed by Wilkinson et al. (2025, Table 1). In the original framework, each guideline is attributed to either FAIR Data (Wilkinson et al. 2016) or FAIR4RS (Barker et al. 2022); this provenance is acknowledged here for traceability, although it is not reproduced as a separate column. Each guideline is operationalised as a set of binary items, one point per item that is met, for a maximum of 79 points (Findable 23, Accessible 9, Interoperable 19, Reusable 28). Where no access restrictions apply, A1.2 is considered automatically satisfied (2/2). The "Assessment rationale" column records the evidence behind each score. The rubric is the one adopted for the TAB-SEB blueprint in Moretti (2026, §6.1.1, Tables 2–6), *Semantic Data Enhancement of Galleries, Libraries, Archives, and Museums: A Metadata Crosswalk Workflow Blueprint*, PhD thesis, University of Bologna and University of Helsinki, so that the two assessments can be compared.

Scope: the workflow blueprint and its executable implementation for the BnF Early Modern case study, published on Protocols.io as "Early Modern COMHIS BnF-Derived Dataset Production Workflow V.1" (DOI 10.17504/protocols.io.kqdg31n5zl25/v1), and the software implementing it on GitHub (ariannamorettj/Early_Modern_BnF_Harmonisation). State as of October 2026.

**Summary.** The workflow meets 64 of 79 items (81.0%): Findability 19/23, Accessibility 8/9, Interoperability 14/19, Reusability 23/28. The main gaps concern the lack of a release or archived snapshot of the software code and of persistent identifiers for the outputs (F1.1, I4, A2), the absence of a formal workflow specification and of a formal run-provenance model (I1), and the lack of shape-based conformance validation (I3).
