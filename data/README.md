### 0. Unified dataset (`unified_dataset.csv`)

**(produced by `main.py`)**

* **Source:** all CSV files found under `data/results_bnf/` (recursively).
* **Process:**

  1. The script scans every subdirectory of `data/results_bnf/`.
  2. Every file with a `.csv` extension is opened (UTF-8 encoding) and its **header row** is read.
  3. All column names found are collected into a set (`colonne_trovate`) to ensure uniqueness.
  4. The full list of unique column names is written/appended to `report.txt` together with a timestamp.
* **Purpose:**

  * To identify **all distinct column headers** present across the CSV files before unifying them.
  * This is essential for building the unified dataset, since you need the **union of all columns** to merge files consistently.
* **Output:**

  * **Console:**

    * Prints each CSV file name and its header list when found.
    * Prints the total number of unique column names.
  * **File:**

    * `report.txt` in append mode, containing:

      * a timestamped section header,
      * the full sorted list of unique column names found in this run.

### 1. **Unified agent datasets**

**(produced by `agents_main.py`)**

* **Source:** `data/result_agents/`, organized by year → role → CSV file.
* **Roles:** `aut` (authors), `edt` (editors), `ill` (illustrators), `pbl` (publishers), `trl` (translators).
* **Process:** for each role, all CSVs from all years are:

  * read as text (all columns as strings),
  * merged into one large dataset,
  * enriched with a `year` column taken from the year folder name,
  * aligned so that **all columns found** across files for that role are included.
* **Output:** 5 CSV files in `data/unified_agents/`

  * `unified_aut.csv`, `unified_edt.csv`, `unified_ill.csv`, `unified_pbl.csv`, `unified_trl.csv`.

### 2. **Actor analysis with key = `actor`**

**(first version of `actors_id_matching.py`)**

* **Source:** the unified CSVs above.
* **Key field:** `actor` column (case-insensitive) — used to identify the actor.
* **Condition:** only actors appearing **more than once** in the dataset are included.
* **Analysis:** for each repeated actor, for each other field in the dataset:

  * collect all **non-empty** values,
  * count how many times each value occurs.
* **Output structure:** JSON dictionary

  ```json
  {
    "hobbes_thomas_bnf_id": {
      "year": [["1651", 2], ["1652", 1]],
      "actor_country": [["England", 3]]
    }
  }
  ```
* **Output location:** one JSON per CSV in `data/actors_matched_ids/` (e.g., `actors_aut.json`).

---

### 3. **Actor analysis with key = normalized `actor_name`**

**(generated by `actors_name_matching.py`)**

* **Source:** the same unified CSVs.
* **Key field:** `actor_name` normalized by:

  * removing periods and commas,
  * compressing multiple spaces into a single space,
  * converting to uppercase.
* **Condition:** only normalized names appearing more than once are included.
* **Analysis:** same as above, but the JSON key is the normalized name string.
* **Output structure:**

  ```json
  {
    "THOMAS HOBBES": {
      "year": [["1651", 2], ["1652", 1]],
      "actor_country": [["ENGLAND", 3]]
    }
  }
  ```
* **Output location:** one JSON per CSV in `data/actors_matched_ids/`.

## **Dataset: Actors Field Cardinality Averages**

**Source script:** `actors_one_to_may_fields_analysis.py`
**Input:** JSON files in `data/actors_matched_ids/`
**Output:**

* One JSON summary per input file in `data/field_to_values_average/` (or chosen `--out-dir`)
  Example:

  ```
  actors_field_cardinality_actors_aut.json
  actors_field_cardinality_actors_trl.json
  ...
  ```
* One combined JSON:

  ```
  actors_field_cardinality_ALL.json
  ```

### **Purpose**

This dataset summarises **how many distinct values** each actor typically has for each metadata field.
It is intended to help distinguish **one-to-many** relationships (fields where actors often have multiple values) from **one-to-one** relationships (fields where actors usually have exactly one value).

### **Methodology**

For each `actors_*.json` file in the input folder:

1. For every actor, count how many `[value, occurrence_count]` tuples exist in each field.
2. Calculate the **average** number of tuples per field, considering only actors that have that field.
3. Save the results as:

   ```json
   {
     "actor_start": 1.0,
     "actor_link_exact": 4.7,
     ...
   }
   ```
4. Repeat for each role-specific dataset (`aut`, `trl`, `pbl`, `edt`, `ill`) and write a per-file summary.
5. Build a **global average** across all input files (`actors_field_cardinality_ALL.json`) by averaging the per-file values for each field.

### **Interpretation**

* **Values ≈ 1.0** → Field is generally one-to-one (most actors have a single value).
* **Values > 1.0** → Field is often one-to-many (actors frequently have multiple values).
* Example:

  ```json
  {
    "year": 2.59,
    "actor_link_exact": 4.70,
    "actor_birth": 1.0
  }
  ```

  Here, `year` and `actor_link_exact` are fields where multiple values per actor are common, while `actor_birth` is consistently one-to-one.

### **Example Use Cases**

* Detect fields that may require **array** or **set** handling in a database model.
* Identify metadata columns that should be checked for **data duplication** or **normalisation**.
* Guide data cleaning or modelling decisions for linked open data conversion.
