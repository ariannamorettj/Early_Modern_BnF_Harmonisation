# 08_sampo_portal — Sampo portal over the knowledge graph

A faceted-search portal over the CHAD-AP knowledge graph that module 07
materialises, built on the [Sampo-UI](https://github.com/SemanticComputing/sampo-ui)
framework (v4: React + Redux client, Node.js/Express server, JSON/JS configs)
and served from an [Oxigraph](https://github.com/oxigraph/oxigraph) SPARQL endpoint.

The graph changes whenever modules 04–07 run again. Nothing in this module is
tied to one version of the data: `portal.py load` rebuilds the triplestore
from whatever module 07 produced last, and the portal reads it live.

```text
08_sampo_portal/
  portal.py              setup / load / serve / dev (cross-platform CLI)
  portal.lock.json       pinned Sampo-UI commit, Oxigraph version + SHA-256
  configs/               the portal itself, mounted into Sampo-UI
    portalConfig.json      portal ID, perspectives, layout, locales
    bnf/search_perspectives/{editions,actors}.json
    bnf/sparql_queries/    SPARQL query templates per perspective
    bnf/translations/      localeEN.json (labels, descriptions, about page)
    bnf/assets/            banner and perspective card images
  triplestore/
    derived.ru             SPARQL Update: the portal layer (see below)
    build_vocab.py         writes the label files in vocab/
    vocab/static.ttl       language, role, type and gender labels
  .tools/ .sampo-ui/ .data/   generated by portal.py, git-ignored
```

## Running it

Requirements: Python with the project dependencies, Git, and Node.js 22
(Sampo-UI's own images use `node:22`; a portable Node install on the PATH is enough).

```bash
python 08_sampo_portal/portal.py setup                  # once, and after changing portal.lock.json
python 08_sampo_portal/portal.py load --profile sample  # after every module 07 run
python 08_sampo_portal/portal.py dev                    # http://localhost:8080
```

`dev` starts three processes and stops all three on Ctrl+C:

| Process | Address | Role |
|---|---|---|
| Oxigraph (read-only) | `http://localhost:7878/query` | SPARQL endpoint |
| Sampo-UI server | `http://localhost:3001/api/v1` | builds and runs the SPARQL queries |
| Sampo-UI client | `http://localhost:8080` | the portal |

Stop `dev` before running `load`: the endpoint keeps the store open, and
`load` swaps in the new store only after it is completely built.

## How the six Sampo steps map onto this module

**1. Prepare the linked data.** Module 07 converts the CSVs to RDF
(`knowledge-graph_merged.nt`). `portal.py load` puts those triples, unchanged,
in the named graph `<https://w3id.org/bnf/portal/graph/chad-ap>`, adds the
vocabulary labels, and runs `triplestore/derived.ru`. The endpoint serves the
union of all graphs.

The CHAD-AP graph gives every edition its own place and publisher node and
keeps names inside Appellation nodes. Sampo facets need shared entities with
a `skos:prefLabel`, so `derived.ru` writes a portal layer into
`<https://w3id.org/bnf/portal/graph/derived>` (namespace `bnfp:`):

| Shortcut | Built from |
|---|---|
| `skos:prefLabel` on editions and actors | title; full name, else surname |
| `bnfp:year`, `bnfp:decade` | the `#ts_year_first` time-span |
| `bnfp:place` → shared `bnfp:Place` with `wgs84:lat/long` | module 04's harmonised place name and TGN coordinates |
| `bnfp:publisher` → shared `bnfp:Publisher` | harmonised publisher name, else the recorded one |
| `bnfp:language` | `R4_embodies / P72_has_language` |
| `bnfp:author`, `editor`, `translator`, `illustrator`, `contributor`; `bnfp:contributedTo`, `bnfp:role` | the role activities on `F28_Expression_Creation` |
| `bnfp:actorType`, `birthYear`, `deathYear`, `foundationYear`, `dissolutionYear`, `gender`, `country` | actor types, events and attribute assignments |

**2. Clone and set up Sampo-UI.** `portal.py setup` clones Sampo-UI at the
commit pinned in `portal.lock.json` into `.sampo-ui/`, links this module's
`configs/` into it as its `configs/` directory, and runs `npm install` for
server and client. It also downloads the pinned Oxigraph binary and verifies
its SHA-256. Two one-line patches let the framework run outside Docker and
on Windows (`SAMPO_PATCHES` in `portal.py`):

- the server serves configs from `SAMPO_CONFIGS_PATH` instead of the fixed
  Docker path `/app/configs`;
- a webpack alias makes `import history from 'History'` resolve to
  `client/src/History.js`; on a case-insensitive filesystem it otherwise
  resolves to the `history` npm package.

**3. General settings.** `configs/portalConfig.json`: portal ID `bnf`, the two
search perspectives, English locale, palette, top bar and main page layout.
The top-bar full-text search is off, because it relies on Jena's text index.
Facet text search uses standard SPARQL `REGEX` (`"textQueryType": "regex"`)
and works on any endpoint.

**4. Perspectives.** `configs/bnf/search_perspectives/`:

- `editions.json`: `lrmoo:F3_Manifestation`. Facets: title, author, other
  contributors, year range, place, publisher, language. Views: table, map of
  places of publication, editions per decade, SPARQL export. Instance page
  per edition, with a link to the ESTC record when module 06 matched one
  (`rdfs:seeAlso`; the link opens CERL's ESTC search by number, because
  `estc.bl.uk` now redirects to the ESTC home page on CERL, whose record
  pages have no stable URL).
- `actors.json`: `obj:Person`, `obj:Organization`. Facets: name, type, role,
  gender, country, birth and death year ranges. Views: table, births per
  decade, export. Instance page per actor.

Page URLs use the ARK local id (`/editions/page/cb31015462k`), and
`URITemplate` maps it back to the `#about` IRI.

**5. SPARQL query templates.** `configs/bnf/sparql_queries/`: the result-set
property blocks, the map query and the chart queries, written against the
`bnfp:` layer and the CHAD-AP graph. Both perspectives replace Sampo-UI's
result-set template with `facetResultSetQueryLateral`
(`SparqlQueriesShared.js`), which wraps the property block in `LATERAL`:
Oxigraph then evaluates the properties only for the 20 rows of the page
instead of every instance (actors table on the full graph: 95 s → 7 s).

**6. UI and localisation.** `configs/bnf/translations/localeEN.json` holds the
portal texts and every property and facet label. The map (Leaflet) and the
line charts (ApexCharts) are configured in the perspective JSONs.

## Endpoint configuration

The perspective configs set `"url": "SPARQL_ENDPOINT"`, a placeholder that is
not a URL, so the Sampo-UI server falls back to the `SPARQL_ENDPOINT`
environment variable. `portal.py dev` sets it to the local Oxigraph; a
deployment only sets a different value.

## Labels

`triplestore/build_vocab.py` writes `vocab/static.ttl` offline (ISO 639-2
languages via pycountry, AAT roles, CHAD-AP types and genders). Country labels
come from id.loc.gov and need network access, so that step is opt-in:

```bash
python 08_sampo_portal/triplestore/build_vocab.py --countries \
    --graph 06_mapping/output/bnf_actors_enriched.csv
```

`--graph` accepts any text file containing the IRIs (a graph dump or the
actors CSV). It writes `vocab/countries.nt` and fetches only codes not
already in it. The committed file covers the 73 LOC country codes of the
current 92,780 actors. The BnF-specific codes (`data.bnf.fr/vocabulary/countrycodes/...`)
have no LOC label and show their code.

## Deploying

Sampo-UI's production image takes the configs directory as a mount:
`configs/` here is exactly what goes to `/app/configs`. Point
`SPARQL_ENDPOINT` at an Oxigraph (or Fuseki) endpoint loaded with the same
three graphs (`portal.py load` shows the commands).

## Known limits

- The top-bar full-text search and the Network view are disabled: the first
  needs a Jena text index, the second Sampo's external network-analysis
  service.
- Data problems found while building the portal, since fixed where they
  originate: organisation names left as serialised literals (`"France"@fr`,
  module 04 assembly), wrong TGN homonyms for ten places including Bordeaux
  (module 04 place table, `verify_tgn_table.py` / `fix_tgn_table.py`), and
  foundation/dissolution events minted for persons (module 07 preprocess).
- On the full graph the facet counts over 814,031 editions take 20-30 s
  with Oxigraph; tables, map and charts answer in 1-15 s.
